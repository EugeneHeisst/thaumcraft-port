# Issues checked on 2026-11-06

Minecraft 1.21.1, NeoForge 21.1.256, Java 21. The disposable dedicated-server audit uses the installed production mod set, replacing only the Thaumcraft jar: baseline 0.17.191, candidate 0.17.192. It never uses the production world or the user's desktop.

## #20: filling jars directly from an alembic

The original `BlockMetalDevice.onBlockActivated` handles held empty/filled regular and void jars. The port retained phial extraction and label interactions but omitted the jar transfer entirely. A held jar fell through to the alembic's knock interaction.

`WardedJarBlock.JarItem.onItemUseFirst` now transfers before that fallback. Regular jars stop at 64 units and leave any remainder in the alembic. Void jars consume all compatible essentia while retaining at most 64 units. Contents and label filters must match; incompatible/full regular jars do not lose contents or get placed. Only one jar from a stack is changed; both hands and creative-mode stacks are covered. Server-side changes synchronize the inventory and block entity; client prediction does not debit essentia. The alembic's label remains intact.

The audit invokes the actual `ServerPlayerGameMode.useItemOn`, rather than directly invoking the new helper. Cases cover empty and partial jars, labels, full and partial void jars, stacked empty jars, offhand use, creative mode, and rejection of incompatible aspects, labels and full regular jars.

## #20: villagers never restock

Setting `VillagerData.profession` does not rebuild vanilla's cached brain behaviors. The village factory and legacy-entity conversion assigned Thaumcraft professions after construction, retaining the unemployed villager's job predicates until entity reload. Both paths now call `refreshBrain` after assigning the profession.

The Arcane Workbench also was not a wizard job site: only the Crucible was registered. Both are now valid wizard workstations under the same existing POI type. The banker's Hungry Chest and ordinary vanilla restock timing remain in use.

The audit creates villagers through the actual village factory and converts actual legacy wizard/banker entities. They naturally claim their workstation and restock exhausted offers during two consecutive game days. Saved-and-reloaded wizard/banker controls pass on the baseline, isolating the cached-brain problem from a generic restocking or fixture failure. The audit drives ordinary entity ticks because a playerless dedicated server otherwise leaves the fixture entities idle; it never calls `restock()` or assigns job-site memory itself.

## #21: Pechs in the Outer Lands

The original `EntityPech.getCanSpawnHere` excludes the tainted biome and, outside dimension 0, accepts only the original Magical Forest and Eerie biomes. The port checked the broad magical-biome tag and nearby population but omitted these restrictions. The Outer Lands carry the magical tag, making their Pech spawn-list entry eligible.

The native spawn predicate now restores the original dimension/biome checks, retaining light/floor rules, the local population cap and the original forest exception in other dimensions. Existing entities and command-created Pechs are not deleted.

Native `SpawnPlacements.checkSpawnRules` checks use dark enclosed rooms that separately pass vanilla monster rules: Outer Lands, Overworld Magical Forest, tainted land and a Magical Forest placed in another dimension. The baseline allows Outer Lands and tainted-land spawning; the candidate rejects both while allowing the two valid forest cases.
